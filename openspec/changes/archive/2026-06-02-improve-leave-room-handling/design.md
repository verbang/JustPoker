## Context

当前 JustPoker 的"离开房间"功能实现非常简单：客户端直接发送 LEAVE_ROOM 事件，服务端直接从 roomPlayers Map 中删除玩家记录，不考虑任何游戏状态。这导致了多个边界问题：

1. **无确认机制**：玩家可以误触离开按钮
2. **游戏状态破坏**：游戏中离开不会触发弃牌逻辑，可能导致游戏卡住
3. **资源泄漏**：行动超时计时器、倒计时等不会被清理
4. **房主问题**：房主离开后 hostId 悬空

现有架构中，断线重连机制已经实现了游戏中的玩家状态管理（30秒重连窗口、自动弃牌等），但这些逻辑与"主动离开"是分开的。

## Goals / Non-Goals

**Goals:**
- 提供离开房间确认弹窗，根据游戏状态显示差异化提示
- 游戏中离开时自动弃牌并正确清理游戏状态
- 准备阶段离开时取消倒计时并释放座位
- 房主离开时自动转移房主权限
- 保持与现有断线重连机制的兼容性

**Non-Goals:**
- 不修改断线重连的核心逻辑（30秒超时、自动弃牌）
- 不增加离开房间的筹码惩罚机制（已投入筹码不退还已是惩罚）
- 不限制玩家频繁加入/离开房间
- 不实现"旁观者"模式
- 不调整离开按钮的位置（暂不调整）

## Decisions

### Decision 1: 确认弹窗实现方式

**选择**：使用原生 `confirm()` 对话框

**理由**：
- 实现简单，无需新增 UI 组件
- 跨平台兼容性好
- 符合"危险操作确认"的 UX 模式

**备选方案**：
- 自定义 Modal 组件：更美观，但增加开发成本
- Vuetify/Element Plus 对话框：需要引入 UI 库

### Decision 2: 游戏中离开的处理策略

**选择**：复用现有的 `forceFold()` 逻辑，然后移除玩家

**理由**：
- forceFold 已经处理了弃牌后的游戏推进逻辑
- 保持与断线超时后自动弃牌的一致性
- 减少代码重复

**处理流程**：
```
LEAVE_ROOM (游戏中)
    │
    ├─ 1. 清除行动超时计时器（如果是当前行动玩家）
    ├─ 2. 调用 forceFold() 弃牌
    ├─ 3. 检查游戏是否结束（只剩1人）
    ├─ 4. 如果游戏继续，安排下一个玩家的行动超时
    ├─ 5. 从 roomPlayers 中移除玩家
    └─ 6. 广播 ROOM_UPDATE 和 PLAYER_LEFT
```

### Decision 3: 房主转移策略

**选择**：房主离开时，按照座位次序自动转移房主给下一个座位的玩家

**理由**：
- 座位号是确定性排序，避免随机性
- 按座位次序转移符合直觉（类似庄家轮转）
- 如果房间无人，则房间会在2分钟后被清理定时器删除

**处理逻辑**：
```
房主离开时：
1. 获取当前房主的座位号
2. 查找座位号 > 当前座位号的最小座位玩家
3. 如果找到，转移房主权限
4. 如果未找到（当前房主座位号最大），从最小座位号开始查找
5. 如果房间无其他玩家，不设置新房主
```

### Decision 4: 客户端状态判断

**选择**：客户端根据 RoomPlayer.status 和 gameStore.gameState 判断当前状态

**状态判断逻辑**：
```typescript
const myStatus = myPlayer.status; // 'joined' | 'seated' | 'ready' | 'playing'
const isGameInProgress = gameStore.gameState?.status === 'playing';

if (isGameInProgress && myStatus === 'playing') {
  // 游戏中离开：提示"已投入筹码将不退还"
} else if (myStatus === 'ready') {
  // 准备阶段离开：提示"确定离开吗？"
} else {
  // 未选座/已选座：简单确认
}
```

### Decision 5: 事件通知策略

**选择**：复用现有的 PLAYER_LEFT 事件，增加 `reason` 字段区分离开原因

**理由**：
- 减少新增事件的复杂度
- 客户端可以根据 reason 显示不同的提示（如"XXX 离开了房间" vs "XXX 断线重连中"）

**事件格式**：
```typescript
{
  userId: string;
  reason: 'leave' | 'disconnect' | 'timeout';
  reconnecting?: boolean;  // 仅 disconnect 时为 true
}
```

### Decision 6: 离开玩家在比分板上的显示

**选择**：在比分板上保留离开玩家的信息，字体颜色置灰

**理由**：
- 保留历史记录，方便其他玩家了解游戏进程
- 置灰显示明确表示该玩家已离开
- 不影响其他玩家继续游戏

**实现方式**：
- Scoreboard 组件接收 leftPlayers 数据
- 已离开玩家显示为灰色字体
- 状态显示为"已离开"

**[Risk] forceFold 可能失败**
→ Mitigation：forceFold 已有 try-catch 包裹，失败时记录日志但仍继续移除玩家

**[Risk] 竞态条件：玩家在倒计时最后一刻离开**
→ Mitigation：服务端在 LEAVE_ROOM 处理时检查并取消倒计时，使用现有的 countdowns Map

**[Risk] 房主转移时目标玩家刚好离开**
→ Mitigation：使用循环查找下一个可用玩家，如果无人则不设置新房主

**[Trade-off] 使用原生 confirm() 而非自定义弹窗**
→ 原生弹窗不够美观，但实现快速且可靠
→ 未来可以替换为自定义弹窗，不影响后端逻辑

**[Trade-off] 复用 PLAYER_LEFT 事件而非新增事件**
→ 减少事件数量，但增加了事件数据的复杂度
→ 需要确保旧客户端兼容（reason 字段可选）
