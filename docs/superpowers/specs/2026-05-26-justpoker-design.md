# JustPoker - 在线德州扑克平台设计文档

## 概述

JustPoker 是一个面向好友的在线德州扑克网页平台，支持最多10人同时在线对战。用户无需安装客户端，通过浏览器即可参与游戏。

### 核心特性

- 好友间通过链接/房间号加入
- 最多10人同时在线对战
- 支持中途加入牌桌
- 游戏中发送表情
- 操作计时器（每轮下注30秒超时自动弃牌）
- 筹码管理（初始筹码、重新买入、比分板）
- 战绩统计（总局数、胜率、总盈亏）
- 音效系统（加入/离开、发牌、翻牌、投注、弃牌、表情、结算）

## 技术栈

| 层级 | 技术 | 用途 | 成本 |
|------|------|------|------|
| **前端** | Vue.js + TypeScript | 游戏界面、用户交互 | 免费 |
| **后端** | Node.js + Express + Socket.io | 游戏逻辑、实时通信 | 免费 |
| **数据库** | Supabase (PostgreSQL) | 用户数据、游戏记录存储 | 免费 |
| **前端部署** | Vercel | 托管前端静态资源 | 免费 |
| **后端部署** | Render | 托管后端服务 | 免费 |

### 技术选型理由

1. **全栈JavaScript** — 前后端统一语言，学习成本最低
2. **Socket.io** — 内置房间系统、自动重连、广播功能，专为实时应用设计
3. **Vue.js** — 学习曲线平缓，中文文档完善，适合快速开发
4. **Supabase** — 免费托管PostgreSQL，自带管理界面，无需维护数据库服务器
5. **云平台部署** — 零运维，自动部署，免费额度足够开发和小规模使用

## 德州扑克游戏规则

### 游戏流程

1. **发底牌** — 每人发2张底牌（只有自己可见）
2. **翻牌前下注** — 从大盲注左边开始，依次选择**弃牌/过牌/跟注/加注/全下**
3. **翻牌** — 发3张公共牌（所有人可见）
4. **翻牌后下注** — 新一轮下注（从庄家左边第一个未弃牌玩家开始）
5. **转牌** — 发第4张公共牌
6. **转牌后下注** — 新一轮下注
7. **河牌** — 发第5张公共牌
8. **河牌后下注** — 最后一轮下注
9. **摊牌** — 比较牌型，最大者赢得底池

### 自动开始机制

- 当房间内 **2名或以上玩家入座** 后，游戏自动开始
- 当前局结束后，**3秒延迟**后自动开始下一局
- 筹码为0的玩家状态变为 `out`，需重新买入才能继续

### 牌型大小（从大到小）

| 牌型 | 英文 | 说明 | 示例 |
|------|------|------|------|
| 皇家同花顺 | Royal Flush | 同花色的 A、K、Q、J、10 | ♠A ♠K ♠Q ♠J ♠10 |
| 同花顺 | Straight Flush | 同花色的五张连续牌 | ♥9 ♥8 ♥7 ♥6 ♥5 |
| 四条 | Four of a Kind | 四张相同点数的牌 | ♠K ♥K ♦K ♣K ♠A |
| 葫芦 | Full House | 三条加一对 | ♠J ♥J ♦J ♣8 ♠8 |
| 同花 | Flush | 五张同花色的牌 | ♠K ♠J ♠9 ♠7 ♠3 |
| 顺子 | Straight | 五张连续牌 | ♠10 ♥9 ♦8 ♣7 ♠6 |
| 三条 | Three of a Kind | 三张相同点数的牌 | ♠Q ♥Q ♦Q ♠J ♥9 |
| 两对 | Two Pair | 两个不同的对子 | ♠A ♥A ♦K ♣K ♠10 |
| 一对 | One Pair | 一个对子 | ♠J ♥J ♦A ♣K ♠9 |
| 高牌 | High Card | 不符合以上任何牌型 | ♠A ♥K ♦J ♣9 ♠7 |

### 特殊规则

#### 盲注系统

- **小盲注 (Small Blind)**：庄家左边第一位，下最小注的一半
- **大盲注 (Big Blind)**：庄家左边第二位，下最小注
- 每局结束后，庄家位置顺时针移动

#### 下注规则

- **无限注 (No Limit)**：每次下注至少等于大盲注，上限为玩家筹码
- **下注轮次**：每轮下注直到所有未弃牌玩家下注金额相同
- **全下 (All-in)**：押上所有筹码，创建边池

#### 边池计算

当玩家全下时，需要计算边池：

- 主池：所有玩家都有资格赢取
- 边池：只有参与边池的玩家有资格赢取
- 多个全下时可能产生多个边池

### 页面结构

```

/profile (个人中心)
├── 战绩统计
└── 历史记录
```

### 移动端横屏优先

JustPoker 的主要受众是手机浏览器玩家，游戏房间页必须以**手机横屏游玩**作为核心体验目标。后续新增或调整游戏内 UI 时，应优先验证 667×375、736×414、844×390 等常见横屏视口。

**布局要求：**
- 游戏房间在横屏小屏下采用“牌桌主区域 + 右侧控制区”的两栏布局，避免操作面板、表情和比分板纵向堆叠挤压牌桌。
- 房间号等低频信息压缩为左上角小型 HUD，主要屏幕空间保留给牌桌、手牌、公共牌和行动按钮。
- 牌桌、座位、公共牌、玩家头像、筹码、位置徽章需要随屏幕高度收缩，保证 10 人桌仍能完整显示。
- 操作按钮保持可触控尺寸，横屏小屏下以 2 列网格排列，滑块单独占满一行。
- 表情面板和比分板位于右侧控制区；比分板允许内部滚动，不应撑破整屏布局。
- 竖屏仍可浏览与操作，但游戏进行中的首要适配方向是横屏，必要时可在后续增加横屏提示。

### 首页功能

1. **创建房间**
   - 设置昵称（2-10字符，中文/英文/数字，不可重名）
   - 设置房间初始筹码（默认100，可选100/200/500）
   - 生成2位随机房间号（10-99）
   - 创建后以房主身份进入，状态为 `seated`

2. **加入房间**
   - 输入2位房间号
   - 设置昵称
   - 设置带入筹码（默认100，可选100/200/500）
   - 进入后状态为 `joined`

3. **音效开关**
   - 开启/关闭游戏音效
   - 无背景音乐，仅游戏动作音效

### 游戏桌面设计

- 椭圆形牌桌，玩家顺时针围坐
- 最多10个玩家位置
- 底部中央为当前玩家（1号位）
- 其他玩家按顺时针方向依次排列
- 手机横屏下牌桌占据主区域，右侧固定保留操作、表情、比分板空间；不得依赖桌面端固定高度。

### 玩家位置布局

- 2人桌：对坐（180度间隔）
- 3人桌：三角形（120度间隔）
- 4人桌：方形（90度间隔）
- 5人桌：五边形（72度间隔）
- 6人桌：六边形（60度间隔）
- 7-10人桌：均匀分布（按比例计算角度）

### 操作面板

- **弃牌** — 放弃本局
- **过牌 (Check)** — 不加注，将行动权传递给下一位玩家（仅当无需跟注时可用）
- **跟注 (Call)** — 跟当前最大注额
- **加注 (Raise)** — 增加注额（滑块选择金额，最小加注额 = 当前注额 + 大盲注）
- **全下 (All-in)** — 押上所有筹码

**操作逻辑：**
- 当 `myBet >= currentBet` 时，显示"过牌"按钮（绿色）
- 当 `myBet < currentBet` 时，显示"跟注"按钮（蓝色），显示需跟注金额
- 加注滑块范围：`[currentBet + minRaise, playerChips]`
- 弃牌后状态变为 `folded`，不再参与本局

### 表情系统

12个预设表情：👍 🎉 😮 😢 😡 🤔 💰 🃏 🍀 😎 🙏 ⏰

**功能规则：**
- 点击表情直接发送，通过 Socket 广播给房间内所有玩家
- 表情在发送者**头顶浮现**，以**向上漂浮动画**展示
- 最多同时显示3个表情（超出时移除最早的）
- **3秒后自动淡出消失**
- 5秒内连续发送5个表情触发10秒冷却
- 冷却期间按钮禁用，显示"太快了，停一下"

**前端实现：**
- `RoomView` 维护 `activeEmojis` 数组，接收 `new-emoji` 事件后添加
- `GameTable` 按 userId 过滤表情传给对应 `PlayerSeat`
- `PlayerSeat` 中 `.emoji-container` 使用 CSS `@keyframes emoji-rise` 动画
- `transition-group` 管理表情的进入/离开动画

### 座位选择

- 加入房间后显示**圆桌形式**的座位选择界面（与游戏进行中布局一致）
- 10个座位围绕椭圆形牌桌排列，玩家可直观看到上下家位置
- 空座位绿色高亮可选，已占用座位灰色不可选
- 选择座位后进入等待状态（seated）
- **房主创建房间后自动落座1号位**，无需手动选座
- 当前局结束后自动加入下一局
- 游戏间隙可换座

### 第一视角布局

游戏进行时采用**第一人称视角**：
- 当前玩家（我）**固定显示在屏幕底部**
- 其他玩家按**顺时针方向**从左侧向右侧展开排列
- 无论实际座位号如何，视觉上始终保持"我"在底部
- 当前操作玩家（轮到其行动）用**黄色边框高亮**显示
- 庄家位（D）、小盲位（SB）、大盲位（BB）在玩家头像上方用彩色徽章标识

**座位编号规则：**
- 1号位在圆桌底部（6点钟方向）
- 2号位在左下方（顺时针排列）
- 依此类推，10号位在右下方

### 中途加入

- 游戏进行中新玩家可加入房间
- 新玩家需设置昵称和带入筹码
- 新玩家状态为 `joined`，需选择座位
- 选择座位后状态为 `seated`，等待当前局结束
- 当前局结束后自动加入下一局
- 等待期间可观战和发送表情

### 邀请链接

- 创建房间后自动生成邀请链接
- 链接格式：`https://justpoker.vercel.app/room/{room_code}`
- 点击链接直接跳转到加入房间页面
- 房间号自动填充

### 牌面花色颜色

为提高牌面可读性，花色使用对应颜色显示：
- **红心 ♥ / 方块 ♦** → 红色 (#d32f2f)
- **黑桃 ♠ / 梅花 ♣** → 黑色 (#212121)
- 牌背使用蓝色渐变 (`linear-gradient(135deg, #1565c0, #0d47a1)`)
- 空位公共牌显示虚线边框占位符

### 手牌牌型提示

游戏过程中**实时显示当前最佳牌型**，帮助玩家快速判断牌力：
- 位于游戏桌面与操作面板之间
- 仅在翻牌后（≥3张公共牌）显示
- 使用 `client/src/utils/handEvaluator.ts` 前端评估器
- 牌型名称使用中文：皇家同花顺、同花顺、四条、葫芦、同花、顺子、三条、两对、一对、高牌
- **强牌高亮**：四条及以上用橙红色 (#ff5722)，葫芦用粉色 (#e91e63)，三条用绿色 (#4caf50)

### 筹码规则

1. **创建房间**：设置初始筹码（100/200/500）
2. **加入房间**：设置带入筹码（100/200/500）
3. **出局处理**：筹码输光后，本局结束时强制重新买入
4. **重新买入**：选择筹码档次（100/200/500），记录在比分板
5. **最终结算**：根据总投入和当前筹码计算盈亏

### 比分板

显示内容：
- 玩家昵称
- 初始筹码
- 重新买入总额
- 总投入（初始 + 重新买入）
- 当前筹码
- 盈亏（当前筹码 - 总投入）

### 音效设计

| 场景 | 音效 |
|------|------|
| 加入/离开牌桌 | 提示音 |
| 发牌/翻牌 | 纸牌声 |
| 下注/跟注/加注 | 筹码声 |
| 弃牌 | 纸牌放下声 |
| 发送表情 | 轻快提示音 |
| 赢得底池 | 胜利音效 |
| 游戏结束 | 结算音效 |
| 轮到你操作 | 提示音 |

### Socket 事件设计

**客户端 → 服务器：**
- `join-room` — 加入房间
- `leave-room` — 离开房间
- `player-action` — 玩家操作（弃牌/过牌/跟注/加注/全下）
- `send-emoji` — 发送表情
- `select-seat` — 选择座位
- `rebuy` — 重新买入

**服务器 → 客户端：**
- `room-update` — 房间状态更新
- `game-start` — 游戏开始
- `game-update` — 游戏状态更新
- `player-joined` — 新玩家加入
- `player-left` — 玩家离开
- `new-emoji` — 新表情
- `error` — 错误通知
- `rebuy-required` — 需要重新买入

### API 接口设计

**房间相关：**
- `POST /api/rooms` — 创建房间
- `GET /api/rooms/:id` — 获取房间信息
- `POST /api/rooms/:id/join` — 加入房间

**用户相关：**
- `POST /api/users/register` — 注册（昵称）
- `GET /api/users/:id` — 获取用户信息
- `GET /api/users/:id/stats` — 获取用户战绩

**游戏相关：**
- `GET /api/games/:id` — 获取游戏记录
- `GET /api/games/history` — 获取历史记录

### 玩家状态说明

#### 房间层级 (`PlayerStatus`)

定义在 `shared/types/room.types.ts`，管理玩家在房间中的整体状态：

| 状态 | 含义 | 触发时机 | 可执行操作 |
|------|------|----------|------------|
| **joined** | 已加入，未入座 | 设置昵称进入房间时 | 选择座位、发表情 |
| **seated** | 已入座，未准备 | 选择座位坐下后 | 点击"准备"按钮、观战、发表情 |
| **ready** | 已准备，等待开局 | 点击"准备"按钮后 | 观战、发表情（等待其他玩家 ready） |
| **playing** | 游戏中 | 倒计时结束后 | 弃牌/过牌/跟注/加注/全下 |
| **folded** | 已弃牌 | 点击"弃牌"按钮后 | 仅观战、发表情 |
| **out** | 出局（筹码为0） | 筹码输光时 | 仅观战、重新买入 |

#### 游戏层级 (`GamePlayer.status`)

定义在 `shared/types/game.types.ts`，管理一局游戏中的状态：

| 状态 | 含义 |
|------|------|
| **playing** | 参与中，可操作 |
| **folded** | 已弃牌，等待比牌 |
| **all_in** | 全下，等待比牌 |
| **out** | 出局，本局不参与 |

#### 两层状态对应关系

| 房间状态 | 对应游戏状态 | 说明 |
|----------|-------------|------|
| `seated` | 无（未开局） | 等待点击准备 |
| `ready` | 无（未开局） | 等待倒计时 |
| `playing` | `playing` | 正常参与 |
| `playing` | `folded` | 已弃牌 |
| `playing` | `all_in` | 全下等待比牌 |
| — | `out` | 房间状态仍为 `playing` |
| `out` | — | 需重新买入 |

#### 状态流转图

```
创建/加入房间
      │
      ▼
   ┌────────┐   选择座位   ┌────────┐   点击准备   ┌────────┐   倒计时结束   ┌──────────┐
   │ joined │ ──────────► │ seated │ ──────────► │ ready  │ ──────────► │ playing  │
   └────────┘             └────────┘             └────────┘              └──────────┘
                            ▲    ▲                                       │    ▲
                            │    │          局结束后                       │    │
                            │    │      chips > 0 ───────────────────────┘    │
                            │    │                                           │
                            │    │          弃牌                              │
                            │    └──────────────────────────┐                │
                            │                               ▼                │
                            │                         ┌──────────┐           │
                            │                         │ folded   │           │
                            │                         └──────────┘           │
                            │                                                │
                            │          局结束后                               │
                            │     folded/seated ◄────────────────────────────┘
                            │
                            │          chips = 0
                            │               │
                            │               ▼
                            │         ┌────────┐   重新买入   ┌────────┐
                            └─────────│  out   │ ──────────► │ seated │
                                      └────────┘              └────────┘
```

**关键流转说明：**

| 流转 | 触发条件 | 说明 |
|------|----------|------|
| `joined` → `seated` | 选择座位 | 房主创建房间后自动落座1号位 |
| `seated` → `ready` | 点击"准备"按钮 | 仅 `seated` 状态可操作 |
| `ready` → `playing` | 倒计时 3→2→1→Go! 结束 | 所有 `seated` 玩家都 `ready` 后触发 |
| `playing` → `folded` | 点击"弃牌" | 本局不再参与操作 |
| `playing` → `seated` | 局结束，有剩余筹码 | 需重新点击"准备" |
| `playing` → `out` | 局结束，筹码为0 | 需重新买入 |
| `folded` → `seated` | 局结束 | 弃牌玩家回到等待状态 |
| `out` → `seated` | 重新买入成功 | 获得新筹码，回到等待状态 |

### 表关系

- `users` 1:N `room_players` — 一个用户可加入多个房间
- `rooms` 1:N `room_players` — 一个房间最多10个玩家
- `rooms` 1:N `games` — 一个房间可进行多局游戏
- `games` 1:N `game_actions` — 一局游戏有多个操作
- `games` 1:N `tips` — 一局游戏可有多次打赏
